pfSense acts as the central control point. The first project protects remote access to internal resources. The second manages web services hosted on separate internal servers.

PROJECT 01
VPN · REMOTE ACCESS · FIREWALL

Secure Remote Access with OpenVPN

Implementation of a solution allowing a remote user to access only authorized internal resources through an encrypted tunnel managed by pfSense.

Why was this project needed?

To support remote work and administration without directly exposing internal servers and services to the Internet.

  • Configured pfSense as the firewall and VPN gateway.
  • Deployed the OpenVPN server and remote client profile.
  • Defined access rules between the VPN and LAN.
  • Validated the tunnel, authentication and connectivity.

PROJECT 02
REVERSE PROXY · HTTPS · SNI

Secure Web Architecture with pfSense and HAProxy

Implementation of a reverse proxy that routes multiple HTTPS connections to separate internal servers without publishing real domain names, addresses or sensitive infrastructure details.

Why was this project needed?

A standard NAT rule for public port 443 can point to only one destination. HAProxy inspects the SNI name and automatically selects the matching backend.

  • Installed and enabled HAProxy on pfSense.
  • Created an HTTPS frontend in TCP passthrough mode.
  • Created backends and SNI-based ACL rules.
  • Added WAN rules and validated L4 health checks.
